# Learning Philosophy

Glyt is partly a programming language and partly an experiment in how programming could be learned through creation.

## The destination

The long-term educational success state is:

> **“Wait. I actually understand programming now.”**

The language should help users reach that state naturally through use.

## Understand before memorize

Memorization has a place, but Glyt should not depend on it for ordinary fluency.

When a user encounters a concept, the system should help them understand what it means, why it exists, and how it behaves.

Repeated meaningful use should reinforce the concept.

## Experience creates understanding

A strong learning path is:

1. Have an intention.
2. Try something.
3. See what happens.
4. Understand why.
5. Modify it.
6. Use the understanding somewhere else.
7. Generalize the concept.

This should be more important than completing a sequence of detached exercises.

## Help without dependency

When users are stuck, Glyt should explain what it thinks they were trying to do, identify the problem, and explain how they can change it.

The explanation should support understanding rather than merely replacing the user's thinking with a magical fix.

## Different people, different depth

Some users will want to learn every underlying detail.
Others will mostly want to build things.

Glyt should serve both while still making deeper understanding increasingly accessible.

## Education is part of design research

Programming language decisions should be informed by evidence about how people actually understand systems, especially evidence from education, human-computer interaction, accessibility, and real usage.
