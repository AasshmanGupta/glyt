# Design Principles

These are practical lenses for evaluating Glyt proposals.

## Human-first

Start from what the creator is trying to accomplish.

## Capability without shrinkage

Do not simplify by deleting legitimate power.

## Small core, enormous surface

Keep fundamental mechanisms understandable and derive higher-level conveniences when possible.

## Big understandable concepts

Prefer concepts that form a coherent mental model over fragmented pieces that are only locally simple.

## Progressive disclosure

Reveal complexity when it becomes useful, not merely because the system contains it.

## Beginner magic, expert override

Good defaults should let newcomers succeed quickly. Deeper control should remain reachable.

## One grammar

Domain vocabulary can vary. Core grammatical identity should remain coherent.

## Explainable behavior

Important behavior should be understandable to the person using it.

## Safe experimentation

People should be able to explore powerful capabilities without turning ordinary experimentation into uncontrolled system risk.

## Real software

The language must eventually be capable of producing software that people can actually distribute and trust.

## Learn through making

Learning should happen through meaningful creation wherever possible.

## No attention traps

The system should never confuse engagement with success. Capability gained matters more than minutes spent.
