# Security Policy

## Scope

Glyt is currently a design and documentation project. As implementation
becomes real, this policy will cover security vulnerabilities in Glyt code,
official tooling, release infrastructure, and security-sensitive components
maintained by the project.

## Reporting

For a privately reportable vulnerability, please use GitHub's private security
reporting mechanism when it is enabled for the repository. Do not publish
sensitive exploit details in a public issue before the project has had a
reasonable opportunity to investigate and mitigate the problem.

If private reporting is not yet available, avoid posting sensitive details
publicly and contact the project maintainers through the repository's current
private contact route.

## Coordinated disclosure

The project may temporarily keep security-sensitive implementation details
private while a vulnerability is being investigated or fixed. Once practical,
the project should publish an appropriate advisory or release note describing
the issue, impact, affected versions, and remediation.

## Important distinction

This policy concerns responsible handling of vulnerabilities. It does not
create restrictions on ordinary lawful use of Glyt, and it does not replace
the software licenses governing the project.
