# Glyt

**Advancement without losing soul.**

Glyt is an experimental universal programming language project built around one question:

> **What would a programming language look like if its primary purpose were to make human creation easy, alive, and genuinely capable?**

Glyt is for programmers, future programmers, artists, musicians, YouTubers, scientists, designers, teachers, students, curious people, and people who do not currently think of themselves as technical at all.

The ambition is simple to say and extremely difficult to achieve:

> **Make anyone capable of doing anything easily, without shrinking what they can do.**

## What Glyt is trying to make possible

Glyt should let a person begin with an idea rather than a pile of prerequisites.

A user should be able to explore, experiment, learn, build, understand, go deeper, and eventually control as much of the underlying system as they want.

A beginner should be able to create real software.
An experienced developer should be able to pursue serious technical goals without unnecessary friction.
An explorer should be able to wander.
An achiever should be able to ship.
Both should be using the same underlying language.

## The North Star

> **Advancement without losing soul.**

For Glyt, **soul means the human creator**.

Technology should expand human capability without forcing humans to behave like machines just to operate it.

## Core beliefs

- Ease must not come from removing possibilities.
- Large, understandable concepts are better than tiny concepts that require memorization without understanding.
- Users should become more capable through using Glyt, not more dependent on it.
- Exploration is a valid outcome, not wasted time.
- Fast achievement is also a valid outcome.
- One underlying language should remain coherent across domains.
- Domain experiences may feel dramatically different while the underlying grammar remains one language.
- Complexity is acceptable when it represents real depth. Complexity caused by needless friction is not.
- Users should be able to descend from high-level creation to deep control.
- Powerful experimentation should be possible inside safe environments.
- The community is allowed to surprise Glyt and change its assumptions when evidence supports something better.

## Current status

**Version: 0.1.0 — Foundation Rebuilt**

Glyt is currently a **language-design and community-discovery project**. Its concrete syntax and grammar are intentionally not finalized yet.

This version establishes the project's philosophy, boundaries, design goals, learning philosophy, safety direction, contributor model, relationship to Loom, and roadmap toward actual language design.

## What Glyt is not

Glyt is not currently a compiler implementation repository.

Glyt is not Loom.

Glyt is not an AI replacement for the person creating something.

Glyt is not designed to manipulate attention or maximize time spent inside the tool.

Glyt is not a promise that difficult real-world problems magically disappear. The ambition is to remove unnecessary barriers to expressing and solving them.

## Where the work is right now

### Ready for discovery

- Core philosophy
- Human experience goals
- Learning philosophy
- Capability model
- Safety direction
- Domain model
- Community process
- Research questions

### Intentionally undecided

- Concrete syntax
- Final grammar
- Keyword set
- Type-system design
- Exact control syntax
- Final module syntax
- Error syntax and diagnostic presentation
- Exact standard-library shape

We will not invent these merely because a programming-language repository looks incomplete without them. They should emerge from research, experiments, contributor insight, and repeated use.

## Collaboration

Glyt is a public experiment. People can encounter it, disagree with it, study it, improve it, build experiments around it, or simply follow along.

Ideas, research, design work, examples, documentation, accessibility insight, technical work, and thoughtful criticism can all become part of that process. The project does not assume that its current ideas are complete, and it does not treat the founder as the sole source of good answers.

People who become interested in the project can find the current contribution paths in [CONTRIBUTING.md](CONTRIBUTING.md), Issues, and Discussions.

Technical expertise is valuable. So is the ability to explain that expertise clearly to someone who does not share the same background.

## A final test

Glyt is succeeding when someone who once thought:

> “I could never make that.”

can instead say:

> **“I have an idea. Let me make it.”**

And later:

> **“Wait. I actually understand programming now.”**
